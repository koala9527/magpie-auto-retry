          插件怎么运行

          重试的是请求，不是重启任务

          插件是 Magpie 前面的转接服务：先替 Agent 把请求发出去，临时失败时等一会儿再试，完整成功后把结果交回 Agent。

          Agent → 重试服务 :3430 → Magpie :3425 → 提供商

          1. 先发一次。 默认将 Magpie 管理的 Codex 配为本地转发，重开后生效。模型名和 key 不变；请求经插件转发给本机 Magpie。
          2. 临时失败就等一等。 网络断开、408/425/429/5xx、单次超时，或输出前的空流、临时流错误/断流，会等待后再发同一个请求。
          3. 连续失败，逐次加长等待。 默认参数、关闭抖动时：2 → 4 → 8 → 16 → 32 → 60 → 60…秒。开启抖动时上下浮动约 25%；Retry-After 可以要求更长等待，最长 24 小时。没有重试次数或累计等待上限。
          4. 成功后继续。 原连接还在时，插件把回复交回 Agent，由 Agent 继续任务。等待心跳只是注释，不调用模型，也不检测提供商。
          5. 该结束时就结束。 协议不匹配、content_filter 明确拒绝、401/403、无效请求/模型、余额不足、密钥或证书错误不做无限重试。已经发出文本、思考或工具调用后不从头重试，避免重复输出和执行。
          取消、退出或重启后会怎样？

          取消、断开连接、Agent 退出、插件停止或重启都会结束当前请求。未完成请求只存在内存里，重启后不会复活；非流式客户端自己的 HTTP 总超时仍有效。

          可用率按真实请求结果计算。超过 5 分钟没流量、服务离线时记为未知；心跳不算成功。没有观测就显示 —，不是 100%。

          监听端口在 Magpie 插件选项里修改后重启；上游地址在设置里填写本机 Magpie 地址。恢复默认只回填表单，不会自动保存。

          自动重试运行参数

          默认开启。关闭后新请求只尝试一次，正在等待重试的请求也会停止。

          默认开启。等待时间上下随机浮动约 25%，不超过最大退避，避免多个请求一起重试。

          秒

          第一次重试前等多久。默认 2 秒，可设 0.1–60 秒；之后逐次加倍。

          秒

          每次普通等待的上限，默认 60 秒（0.1–3600）。不是重试总时限；Retry-After 可要求更久，最长 24 小时。

          秒

          一次尝试等响应头、读完非流式回复的上限。默认 120 秒（1–600），不是任务总时限。

          秒

          上游流多久没数据就算中断。默认 120 秒（1–600）；收到数据重新计时，已输出后不重放。

          秒

          默认每 10 秒发一条流式等待注释（1–30）。不会额外调用模型，也不是探活。

          个

          默认同时接待 32 个（1–256）；推理、请求上传阶段和模型列表共用名额。满了返回 429，不是重试次数。

          天

          统计和故障记录保留多久，默认 30 天（1–90）。不是保存聊天记录。

          填本机 Magpie 地址，默认 3425；不是提供商网址，也不要填插件自己的 3430 端口。

          读取设置后显示当前退避规则。编辑只改变表单，保存才会生效。
